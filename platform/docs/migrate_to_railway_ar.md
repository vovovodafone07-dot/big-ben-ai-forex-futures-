# خطة نقل Big Ben AI كاملة إلى Railway — 2026-11-13

هذه الخطة **لا تحذف Render أو تغيّر تنبيهات TradingView تلقائيًا**. يشمل النقل API ولوحة التحكم وقاعدة البيانات، وخادم الواجهة القديم عند الحاجة. يبقى المؤشر داخل TradingView، وتبقى مهام البحث اليومية داخل GitHub Actions لأن نقل خادم الويب وحده لا ينقل التنبيهات أو المهام المجدولة.

## ما أُعدَّ مسبقًا في فرع النقل
- `Dockerfile`: خادم Big Ben AI Pro ولوحة التحكم، يعمل على المنفذ الذي تحدده Railway في `PORT`، بدون أي تنفيذ صفقات.
- `Dockerfile.legacy`: خدمة `server.py` والواجهة القديمة، **اختيارية** ولا تحل محل Pro.
- `platform/backend/market_data.py`: جلب Barchart `getQuote` الحقيقي بمفتاح مرخص وتطابق رموز صريح، والتمييز بين فوري/متأخر/نهاية اليوم وقياس قدم السعر.
- `platform/tests/test_market_data.py`: اختبارات وهمية للموصل، دون عرض بيانات مصطنعة بوصفها حقيقية.
- وكيل الاعتمادية في GitHub يسمح بتعيين `BIGBEN_BASE_URL` بدل عنوان Render الثابت.
- لا توجد مفاتيح حقيقية في الملفات، ولا ترحيل لبيانات العملاء، ولا نقل تلقائي للمتغيرات السرية.

## المرحلة 1 — تجربة مستقلة (لا قطع للخدمة الحالية)
1. افتح Railway: https://railway.com/new واربط حساب GitHub الذي يملك المستودع الخاص `vovovodafone07-dot/big-ben-ai-forex-futures-`.
2. أنشئ مشروعًا باسم `bigben-ai-staging`، وأضف خدمة من هذا المستودع **على فرع النقل** `feature/railway-portable-migration-2026-11-13` (أو بعد دمج طلب السحب بالمراجعة).
3. اختر Dockerfile الجذر (`Dockerfile`)، واترك `PORT` لتعيينه تلقائيًا من Railway.
4. أضف PostgreSQL إلى **نفس المشروع** من New → Database → PostgreSQL.
5. في متغيرات خدمة API، عيّن `DATABASE_URL` إلى مرجع متغير قاعدة البيانات `${{Postgres.DATABASE_URL}}` (يجب أن يتطابق اسم الخدمة مع اسم قاعدة البيانات الفعلي في Railway).
6. أنشئ قيمًا **جديدة سرية** في Variables وليس في المستودع: `BIGBEN_WEBHOOK_TOKEN` (32 حرفًا على الأقل) و`BIGBEN_DASHBOARD_PASSWORD` (20 حرفًا على الأقل). لا ترسلها في المحادثة أو تضعها في ملفات Git.
7. إن كنت تملك اشتراك Barchart OnDemand الذي يدعم الأسواق المطلوبة، عيّن `BARCHART_API_KEY` وأضف `BIGBEN_BARCHART_SYMBOL_MAP` كـ JSON يطابق **الرموز المثبتة من المزود** مع رموز TradingView. لا نخمن ترجمة العقود.
8. انشر خدمة الاختبار، ثم من Settings → Networking أنشئ Public Domain بنظام HTTPS.

**مهم:** أسعار Railway واستخدام الموارد منفصلان تمامًا عن اشتراكات السوق/Barchart. الخطة المجانية محدودة، وقد تتطلب خدمة مستمرة وقاعدة بيانات اشتراكًا مدفوعًا. لا تدفع أو ترقي قبل الموافقة.

## المرحلة 2 — التحقق الفني قبل النقل
من عنوان Railway الجديد:
- `GET /healthz` يعيد `status=ok` (يتحقق من التشغيل فقط).
- `GET /healthz/integrations` يعيد مؤشرات إعداد الخدمات، دون كشف الأسرار.
- `GET /healthz/storage` يجب أن يعيد `storage=postgres` وليس `ephemeral`. هذا اختبار مهم جدًا؛ نجاح `/healthz` وحده غير كافٍ.
- `GET /dashboard` يطلب كلمة مرور خاصة؛ تأكد أن لوحة التحكم تعرض البيانات الفعلية لا بيانات وهمية.
- `GET /api/data-sources` بعد مصادقة لوحة التحكم يعرض حالة مفاتيح Barchart، ولكن **الإعداد لا يثبت ترخيص السوق**.
- `GET /api/market?symbol=... ` بعد المصادقة يجلب سعرًا من Barchart عند توفر مفتاح وخريطة رموز؛ راقب `quote_mode` و`quote_timestamp` و`fresh_quote` و`usable_for_live_analysis`. لا تعامل الأسعار المتأخرة أو القديمة كإشارة لحظية.
- نفّذ اختبارات GitHub Actions، وتحقق من حالات فشل API والرّموز غير المسموح بها والبيانات المفقودة.
- لا تستخدم بيانات Barchart قبل التحقق الفعلي (قراءات ناجحة لكل رمز، صلاحيات بورصة CME/CBOT/NYMEX/COMEX، وشموع تاريخية M5، وباك تيست مع العقود والـrollover). `getQuote` للسعر، و`getHistory` موجود في `research/barchart_adapter.py` للبحث التاريخي، وليس بديلًا عن إثبات نتائج اختبار فعلية.

**سجل الرموز المراد التحقق منها:** NQ/MNQ, ES/MES, YM/MYM, RTY/M2K, 6E/M6E, CL/MCL, GC/MGC, EURUSD, GBPUSD, USDJPY وغيرها من قائمة المتابعة. الرموز المذكورة هي أسماء أدوات مطلوبة؛ وليست تأكيدًا أن الاشتراك يغطي كل أداة.

## المرحلة 3 — نقل البيانات والتكاملات دون فقد
- هناك قاعدة PostgreSQL مجانية حاليًا في Render باسم `bigben-ai-pro-events-dev`، وحسب حساب Render تنتهي **2026-12-11**. وجودها لا يثبت أن API يستخدمها حاليًا؛ اختبار `/healthz/storage` وإحصاء السجلات مطلوبان قبل الترحيل.
- إذا كانت بها بيانات مهمة: خذ نسخة احتياطية مشفرة باستخدام `pg_dump` من بيئة مخولة للوصول إلى Render DB؛ افحص عدد الصفوف ووقت آخر حدث؛ ثم استعدها على Railway باستخدام `pg_restore` (أو `psql` وفق نوع التفريغ) بعد اختبار العزل. لا يمكن نقل بيانات قاعدة البيانات بمجرد نسخ GitHub.
- لا تنقل كلمة مرور أو رمز webhook القديم إلى Git؛ يجب ضبط أسرار Railway عبر Variables وتدويرها متى لزم.
- في GitHub Actions اضبط `BARCHART_API_KEY` كـ Secret و`BIGBEN_BARCHART_SYMBOL_MAP` كـ Variable للبحث اليومي. النقل إلى Railway **لا ينقل هذه الإعدادات تلقائيًا**.
- عند نجاح الخادم الجديد فقط، اضبط GitHub Actions variable `BIGBEN_BASE_URL` على عنوان Railway الجديد لتوجيه وكيل الاعتمادية.
- إذا أردت نقل الخدمة القديمة كذلك، أنشئ خدمة ثانية منفصلة من المستودع وحدد Dockerfile `Dockerfile.legacy` في إعدادات Railway، وضع `TWELVEDATA_API_KEY` و`TV_WEBHOOK_SECRET` إن كنت ما زلت تحتاج الخدمة القديمة. هذه الخدمة **تعتمد على Twelve Data للفيوتشرز** وقد تفشل لنفس الرموز، لذلك ليست الحل الأساسي.

## المرحلة 4 — ربط TradingView بالنسخة الجديدة
- اترك مؤشرات Pine الحالية كما هي. **النقل لا يثبت أو يحدّث المؤشر تلقائيًا داخل TradingView**.
- أضف تنبيهًا تجريبيًا جديدًا فقط على زوج واحد، من نوع `Any alert() function call`، وأرسل Webhook إلى:
  `https://<your-railway-domain>/v1/tradingview/events`
- أدخل الرمز الجديد داخل إعدادات المؤشر/التنبيه بطريقة خاصة، ولا تلصقه في محادثة.
- تحقق أن التنبيه يظهر في سجل API وقاعدة PostgreSQL وأن التكرارات لا تنشئ صفقات مزدوجة، وأن Entry/SL/TP/RR صحيحة. اختبر إشعارات TradingView للتطبيق إن كانت مفعّلة.
- عند اكتمال الاختبارات، أعد إنشاء تنبيهات الرموز المقصودة على الرابط الجديد. التنبيهات القديمة في TradingView لا تتغير عند تعديل GitHub أو عنوان الخادم.
- لا تُبقِ تنبيهات النسختين تعملان معًا على الهاتف دون ضبط منع التكرار؛ قد تحصل على إشعارات مزدوجة.

## المرحلة 5 — القبول والرجوع عند الفشل
- اختبر تشغيل الخدمات، تخزين Postgres عبر إعادة تشغيل آمنة، ومراقبة M5، وتطابق الرموز والوقت والمنطقة الزمنية، وتحمل انقطاع المزود. 
- قارن سجل الإشارات الجديد مع القديم دون تفعيل تنفيذ صفقات حقيقية أو أي endpoint للوسيط.
- احتفظ بعنوان Render والتنبيهات القديمة كخطة رجوع حتى ينجح العمل المتوازي بدون أخطاء.
- **لا تحذف أي مشروع أو قاعدة بيانات أو تنبيه قبل الحصول على نسخة احتياطية وفحصها والموافقة الصريحة.**

## قيود لم تُحل تلقائيًا
1. اشتراك Barchart ومفتاح API وصلاحيات الرموز والبيانات اللحظية لم تُفحص باستجابة حقيقية؛ يمكن فقط محاكاة الاستجابة في الاختبارات.
2. حزمة البحث الحالية هي خوارزمية proxy مبسطة **وليست مطابقة لقواعد Pine v6.4**؛ لا يجوز ادعاء أن نظام الوكلاء يتعلم تلقائيًا أو يعطي صفقات ناجحة مضمونة.
3. الوصول إلى حساب Railway الجديد واتصال TradingView وإعداد أسرار البورصات هي إجراءات تتطلب تفويض المستخدم. تجهيز الكود لا يساوي نقلًا فعليًا.
4. إذا لم يكن Barchart متاحًا، يعود Endpoint الأسعار في Pro إلى Twelve Data كما في النسخة السابقة؛ وهو ليس حلًا موثوقًا للفيوتشرز حتى يثبت دعم العقود.
